# Gamma Integration

## Objective

Gamma is used as the presentation rendering and generative layer for the
SmartVitra automation system.

Gamma must not own SmartVitra business logic.

Canonical flow:

CommercialBrief
    |
    v
PresentationSpec
    |
    v
GammaPromptBuilder
    |
    v
Gamma Create From Template API
    |
    v
Generated Gamma
    |
    v
Presentation QA
    |
    v
Human approval
    |
    v
Customer delivery

## API strategy

Primary endpoint:

POST /v1.0/generations/from-template

Fallback / experimental endpoint:

POST /v1.0/generations

The SmartVitra 12-slide presentation should be used as the Gamma template.

The template Gamma ID is configured externally and must never be hardcoded.

## Important limitation

Gamma generation is generative rather than a deterministic slide editor.

The API cannot programmatically edit a generated Gamma after creation.

If validation fails, the system must:

1. reject the generation;
2. regenerate with revised input; or
3. route to human review.

## Images

Gamma requires externally accessible image URLs.

Internal storage keys such as:

visits/S00122/photos/V1/problem.jpg

must be resolved to public or sufficiently long-lived URLs before generation.

Localhost and private network URLs cannot be used.

## Before / after

The AFTER image must not be generated by Gamma.

Preferred flow:

real visit photograph
    ->
dedicated image generation pipeline
    ->
validation
    ->
approved generated image
    ->
Gamma

Gamma only renders the approved BEFORE and AFTER assets.

## Generation lifecycle

1. Build PresentationSpec.
2. Build Gamma request.
3. Submit generation.
4. Store generation ID.
5. Poll generation.
6. Store Gamma URL.
7. Download exported PPTX/PDF immediately.
8. Run automatic QA.
9. Mark READY_FOR_REVIEW.
10. Human approval.
11. Customer delivery.

## Validation

A generated presentation must not be automatically delivered solely because
Gamma reports `completed`.

Required QA includes at least:

- exactly 12 slides;
- canonical slide order;
- customer identity;
- proposal number;
- exact price values;
- exact VAT values;
- products actually proposed;
- no unsupported claims;
- no unresolved placeholders;
- fixed SmartVitra slides present;
- required customer photos present;
- before / after generated asset approved.

## Capability spike

Before production integration, test the Create From Template endpoint using the
existing SmartVitra Gamma.

The experiment must determine:

- whether exactly 12 cards are retained;
- how closely layouts are preserved;
- whether fixed slides remain unchanged;
- whether individual card content can be reliably replaced;
- whether provided images land in the intended cards;
- whether pricing is reproduced exactly;
- variability across repeated generations.

At least three generations using identical input should eventually be compared
to estimate generation variance.

## Cost tracking

For every Gamma request record:

- generation ID;
- number of cards;
- credits deducted;
- credits remaining;
- generation duration;
- success / failure;
- QA status.

This will allow calculation of the real per-proposal automation cost.

## Current architectural status

Gamma is retained as an optional presentation renderer rather than being
assumed to be the only production renderer.

The renderer-independent architecture is:

PresentationSpec
    |
    +---- PptxRenderer
    |
    +---- GammaRenderer

The current development priority is to validate deterministic PowerPoint
rendering.

Gamma remains strategically relevant because it may provide:

- generative visual adaptation;
- existing SmartVitra workflow compatibility;
- API-based generation;
- template-based generation;
- automation through platforms such as n8n.

A future production deployment may support both renderers.

Renderer selection may eventually depend on:

- SmartVitra subscription availability;
- commercial workflow;
- proposal type;
- desired generation style;
- generation cost;
- QA requirements.

Gamma integration work already developed must therefore be preserved and not
removed.
